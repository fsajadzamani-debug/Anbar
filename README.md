# انباریار — سامانه انبارداری فولاد تکنیک

سامانه آنلاین و چندکاربره انبار برای **قطعات سیویل (قالب/داربست)، مصالح، مصرفی، ابزارآلات و اموال** در چند انبار و پروژه.
روی **همان Supabase سامانه مدارک** و با **همان نام‌های کاربری و رمزها** کار می‌کند؛ جدول‌ها پیشوند `wh_` دارند و به جدول‌های `dm_` دست نمی‌زنند.

- **اسناد انبار:** رسید · حواله · انتقال بین انبارها · برگشت از مصرف · تعدیل/انبارگردانی — شماره‌گذاری خودکار (`1405-0001` جدا برای هر انبار و هر نوع)
- **کنترل موجودی در دیتابیس:** حواله/انتقال بیشتر از موجودی ثبت نمی‌شود (فقط مدیر انبار با تأیید جداگانه)؛ ثبت سند اتمیک است
- **موجودی لحظه‌ای** همه انبارها در یک جدول (کالا × انبار)، **کاردکس** هر کالا با مانده، **اموال** شماره‌دار با تحویل‌گیرنده و سابقه
- **گزارش‌ها:** کمتر از حداقل · کالای راکد · گردش دوره · مصرف به تفکیک پروژه · قطعات سیویل نزد پروژه‌ها/پیمانکاران
- **چاپ A4** رسید/حواله/انتقال با جدول امضا، چاپ گروهی، خروجی Excel همه‌جا
- **ورود از Excel:** فهرست کالا (شناسنامه کالا) و موجودی اول دوره؛ چسباندن ردیف‌ها از Excel داخل فرم
- ابطال سند (به‌جای حذف)، تاریخچه کامل، به‌روزرسانی زنده بین کاربران، تقویم شمسی، وزیرمتن، پوسته روشن/تیره، موبایل

## راه‌اندازی (یک‌بار، ۵ دقیقه)

### ۱) دیتابیس
1. [supabase.com](https://supabase.com) → پروژه **madarek** → **SQL Editor** → **New query**
2. کل محتوای [`supabase/schema.sql`](supabase/schema.sql) را کپی و **Run** کنید. (اجرای دوباره بی‌خطر است.)

تنظیمات اتصال در [`config.js`](config.js) از قبل روی همان پروژه است.

### ۲) انتشار آنلاین (GitHub Pages)
**Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**
آدرس: `https://fsajadzamani-debug.github.io/anbar/`
(چون سامانه مدارک هم روی همین دامنه است، ورود بین دو برنامه مشترک است.)

### ۳) اولین ورود و تعریف‌ها
مدیر سامانه مدارک خودکار **مدیر انبار** است. با همان نام کاربری وارد شوید و به ترتیب:
1. **مدیریت → انبارها:** انبار مرکزی و انبارهای پروژه‌ها
2. **ورود از اکسل:** فهرست کالاها، سپس موجودی اول دوره هر انبار
3. **مدیریت → کاربران و دسترسی:** برای هر نفر نقش انبار و انبارهای مجاز

| نقش انبار | دسترسی |
|---|---|
| مدیر انبار | همه انبارها + تعریف انبار/کالا/کاربر + ویرایش و ابطال سند |
| ناظر | مشاهده و گزارش همه انبارها، بدون ثبت |
| کاربر انبار | فقط انبارهای تعیین‌شده؛ در هر انبار «انباردار» (ثبت) یا «مشاهده» |

نقش انبار از نقش مدارک جداست؛ مثلاً کسی در مدارک «فقط مشاهده» و در انبار «انباردار» است.
کاربری که فقط برای انبار ساخته شود، در سامانه مدارک «در انتظار تأیید» می‌ماند و به مدارک دسترسی ندارد.

## نسخه ویندوز و تک‌فایلی
هر بار که کد در `main` تغییر کند، GitHub Actions می‌سازد و در **Releases** می‌گذارد:
`Anbaryar-Setup-*.exe` (نصبی) · `Anbaryar-Portable-*.exe` (بدون نصب) · `anbaryar.html` (تک‌فایلی، در مرورگر)

ساخت دستی تک‌فایلی:
```bash
python3 tools/build_single.py --online -o anbaryar.html      # متصل به Supabase
python3 tools/build_single.py --demo   -o anbaryar-demo.html # آزمایشی با داده نمونه، بدون سرور
```

## ساختار
```
index.html, css/, js/          برنامه وب (بدون build)
  js/store.js                  لایه داده (Supabase / حالت آزمایشی محلی)
  js/app.js                    هسته، دسترسی‌ها، منو، داشبورد
  js/docs.js                   اسناد: فهرست، نمایش، فرم ثبت، چاپ
  js/stock.js                  موجودی، کاردکس، کالاها، اموال، گزارش‌ها
  js/admin.js                  انبارها، کاربران، ورود اکسل، تاریخچه، تنظیمات
supabase/schema.sql            جدول‌های wh_، توابع ثبت سند و کنترل موجودی، RLS
tools/build_single.py          ساخت نسخه تک‌فایلی
desktop/                       نسخه ویندوز (Electron)
.github/workflows/windows.yml  ساخت خودکار exe
```

**منطق موجودی:** موجودی ذخیره نمی‌شود، از ردیف اسناد معتبر محاسبه می‌شود (ویو `wh_stock` / `wh_moves`)؛
رسید و برگشتی (+)، حواله (−)، انتقال (− مبدأ / + مقصد)، تعدیل (±). سند باطل‌شده در موجودی اثری ندارد.
